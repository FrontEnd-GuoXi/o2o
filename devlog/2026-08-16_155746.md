本次开发主要完成了两项工作：**后端区域批量导入功能**（Excel 解析 + 数据校验 + 批量入库）和 **管理端前端页面精简优化**（移除冗余布局组件、新增店铺管理弹窗、Logo 重新设计）。

## 一、后端改动

### 1. 新增区域批量导入功能

#### 1.1 新增 AreaImportDTO（Excel 映射类）

- 路径：`src/main/java/com/o2o/dto/AreaImportDTO.java`
- 使用 EasyExcel 的 `@ExcelProperty` 注解映射 Excel 列：
  - `areaName`：列索引 0，表头"区域名称"
  - `priority`：列索引 1，表头"权重优先级"

#### 1.2 DAO 层新增批量插入

- **AreaDao.java**：新增 `batchInsertArea(@Param("areaList") List<Area> areaList)` 方法
- **AreaDaoMapper.xml**：新增 `<insert id="batchInsertArea">`，使用 MyBatis `<foreach>` 动态拼接 VALUES，支持一次性批量插入多条区域记录

#### 1.3 Service 层新增导入逻辑

- 路径：`src/main/java/com/o2o/service/impl/AreaServiceImpl.java`
- `importAreaBatch(MultipartFile file)` 方法实现：
  1. **文件校验**：检查上传文件是否为空
  2. **Excel 解析**：使用 EasyExcel 同步读取并映射为 `AreaImportDTO` 列表
  3. **数据清洗与业务校验**：
     - 区域名称不能为空
     - 区域名称长度不超过 200 字符
     - Excel 内部不能存在重复区域名称
     - priority 为空时默认值 0
  4. **批量入库**：调用 `batchInsertArea` 一次性插入
- 添加 `@Transactional(rollbackFor = Exception.class)` 保证数据一致性
- 所有校验失败均抛出 `BusinessException`，由全局异常处理器统一拦截

#### 1.4 Controller 层新增导入接口

- 路径：`src/main/java/com/o2o/web/AreaController.java`
- 新增 `POST /area/import` 接口，接收 `multipart/form-data` 中的 `file` 参数
- 返回成功导入的数据条数

### 2. 引入 EasyExcel 依赖

- **pom.xml**：添加 `com.alibaba:easyexcel` 依赖，用于 Excel 文件的读写解析

## 三、技术决策

| 决策项 | 选择 | 原因 |
|---|---|---|
| Excel 解析方案 | EasyExcel | 比 POI 更轻量，注解驱动映射，支持大文件流式读取，内存占用低 |
| 批量入库 | MyBatis foreach 动态 SQL | 一次 SQL 插入多条记录，避免逐条 insert 的性能开销 |
| 事务管理 | `@Transactional(rollbackFor = Exception.class)` | 确保批量导入时任一校验失败整体回滚，不产生脏数据 |
| 管理端布局精简 | 仅保留经典布局 | 移除未使用的多布局切换和冗余组件，减少维护成本，降低项目复杂度 |
| 店铺弹窗组件 | Composable 模式（useShopDialog.ts） | 遵循项目规范，模板/样式/逻辑三文件分离，逻辑集中管理 |
